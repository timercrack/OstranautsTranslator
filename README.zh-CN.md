# OstranautsTranslator

Language / 语言: [English](README.md) | [简体中文](README.zh-CN.md)

`OstranautsTranslator.exe` 是一个部署到 `Ostranauts` 游戏目录中的命令行工具，可用于：

- 扫描游戏文本并构建工作区数据库
- 导出源文本用于翻译，并导入外部翻译结果
- 导出运行时翻译文本，并导入运行时漏翻报告
- 调用 DeepSeek 分批翻译术语表和正文文本
- 导出或部署游戏内中文 mod

## 从 Release 安装

普通玩家直接下载 release zip，然后把压缩包解压到游戏根目录，也就是包含 `Ostranauts.exe` 的那个文件夹。

release 包内包含这些路径：

- `BepInEx\plugins\OstranautsTranslator\`
- `OstranautsTranslator\`
- `Ostranauts_Data\Mods\loading_order.json`
- `Ostranauts_Data\Mods\OstranautsTranslate\`

解压前先关闭游戏。解压完成后启动游戏；如果你想打开状态窗口，可以按 `F6`。

## 应该从哪里运行

- 解决方案构建完成后，工具会被复制到：`<game root>\OstranautsTranslator\`
- 直接从该目录运行 `OstranautsTranslator.exe`
- 工具会自动把 **exe 所在目录的父目录** 视为游戏根目录

固定路径和标识如下：

- 游戏根目录：`<exe dir>\..`
- 工作区：`<game root>\OstranautsTranslator\workspace`
- 主数据库：`<game root>\OstranautsTranslator\workspace\corpus.sqlite`
- 原生 mod 输出根目录：`<game root>\Ostranauts_Data\Mods`
- 原生 mod ID：`OstranautsTranslate`
- 原生 mod 名称：`OstranautsTranslate`

无参数运行 exe 时，会启动自动刷新流程。

`-t` 支持三种写法：

- `-tzh`
- `-t=zh`
- `-t zh`

下面的示例默认使用推荐的短写法。

## 自动刷新

1. scan
2. generate
3. glossary
4. translate
5. deploy

当需要重新生成术语表时，自动流程会通过 `py` 或 `python` 调用随包附带的 `generate_generic_glossary.py`，因此机器上需要能用 Python。

如果你想在“已记录版本”和“已部署 mod 版本”一致时仍然强制执行同样的五步流程，可以运行：

- `OstranautsTranslator.exe rebuild`
- `OstranautsTranslator.exe rebuild -tzh`

如果你想列出支持的目标语言，可以运行：

- `OstranautsTranslator.exe -l`

输出内容包括：

- CLI 参数名
- 英文语言名
- 语言本地名

## 构建

在仓库根目录运行：

- `msbuild .\OstranautsTranslator.sln /p:Configuration=Release /nologo /verbosity:quiet /clp:Summary`

默认情况下，解决方案构建会：

- 把插件 DLL 和 `notosans` 复制到 `BepInEx\plugins\OstranautsTranslator\`
- 把 `OstranautsTranslator.exe` 及其依赖复制到 `<game root>\OstranautsTranslator\`
- 把仓库根目录的 `config-example.ini` 复制到构建输出目录和已部署的 exe 目录
- 如果存在仓库根目录的 `config.ini`，也把它复制到构建输出目录和已部署的 exe 目录
- 把 `tmp\generate_generic_glossary.py` 复制到构建输出目录和已部署的 exe 目录，并重命名为 `generate_generic_glossary.py`

运行时，插件会从游戏的 Unity 资源 `Resources/version` 读取 UI 中显示的真实游戏版本，并把它保存到 `BepInEx\config\OstranautsTranslator.cfg`。如果版本发生变化，插件会在日志和状态窗口里提醒你重新运行 `OstranautsTranslator.exe` 以刷新翻译。游戏更新后，最好先启动一次游戏，让插件记录新的版本，再执行导出或部署。

## 生成 Release Zip

在仓库根目录运行：

- `.\tools\create-release.ps1`

默认情况下，该脚本会：

- 运行解决方案级 `Release` 构建
- 从 `<game root>\BepInEx\plugins\OstranautsTranslator` 复制已部署的插件包
- 从 `<game root>\OstranautsTranslator` 复制已部署的工具目录
- 从 release 包中排除 `config.ini` 和工作区数据
- 复制 `loading_order.json` 和已部署的 `OstranautsTranslate` mod
- 在 `artifacts\release\v<version>\` 下写出 zip，以及英文、简体中文和双语版 release 说明文件

生成的 zip 目录结构可以直接解压到游戏根目录。

## 配置文件

仓库根目录内已提交模板文件：`config-example.ini`。

用法：

1. 把 `config-example.ini` 复制为 `config.ini`
2. 只修改 `[LLMTranslate] ApiKey`
3. 保持 `config.ini` 位于仓库根目录，然后运行 `msbuild`
4. 构建会自动把 `config.ini` 复制到已部署的 exe 旁边

### INI 分节

`config.ini` 使用这三个节：

- `[LLMTranslate]`：DeepSeek 接口地址和通用请求参数
- `[TranslateGlossary]`：术语表翻译提示词及开关
- `[TranslateLlm]`：正文翻译提示词及开关

说明：

- `BatchSize`、`Temperature`、`MaxTokens` 以及模型和接口地址等值都在 `[LLMTranslate]` 下
- `SystemPrompt` 需要分别在 `[TranslateGlossary]` 和 `[TranslateLlm]` 中单独配置

## 工作区目录结构

工具使用如下目录布局：

- `workspace\corpus.sqlite`：主数据库，包含源文本和翻译表
- `workspace\reference\glossary.json`：通用术语表
- `workspace\reference\glossary-en-to-<to>.json`：目标语言术语表
- `workspace\exports\source\`：导出的源文本
- `workspace\imports\translations\`：导入的正文翻译
- `workspace\imports\runtime-miss\`：导入的运行时漏翻报告
- `workspace\exports\runtime\`：导出的运行时文本

主数据库表包括：

- `native_mod_source`
- `runtime_source`
- `translate_<lang>`

## 命令

以下所有命令都默认你是在游戏目录中的已部署 `OstranautsTranslator.exe` 上运行。

### 列出支持的目标语言

- `OstranautsTranslator.exe -l`

会输出：

- CLI 参数名
- 英文语言名
- 语言本地名

### 扫描游戏文本

用于重建或刷新 `workspace\corpus.sqlite` 中的源数据。

- `OstranautsTranslator.exe scan`

### 生成通用术语表

用于通过 exe 调用随包附带的 `generate_generic_glossary.py` 辅助脚本。

- `OstranautsTranslator.exe generate`

### 强制完整重建

用于无条件执行完整刷新流程，而不等待版本不匹配。

- `OstranautsTranslator.exe rebuild`
- `OstranautsTranslator.exe rebuild -tzh`

支持参数：

- `-t<lang>`

此命令总是执行和自动刷新相同的五个阶段：

1. scan
2. generate
3. glossary
4. translate
5. deploy

### 导出源文本

用于导出 JSONL，供外部翻译流程或模型使用。

- `OstranautsTranslator.exe source -tzh`

支持参数：

- `-t<lang>`：目标语言；省略时默认使用系统语言

此命令始终包含已翻译的条目。

导出路径：

- `workspace\exports\source\source-en-to-<to>.jsonl`

### 导入外部翻译

用于把外部 JSONL 翻译结果写回数据库。

- `OstranautsTranslator.exe import -tzh`

支持参数：

- `-t<lang>`

默认导入路径顺序：

1. `workspace\imports\translations\translations-en-to-<to>.jsonl`
2. 如果该文件不存在，则回退到 `workspace\exports\source\source-en-to-<to>.jsonl`

导入 JSONL 格式使用这些定位字段：

- `source_kind`
- `source_id` 或 `source_key`

导入记录会作为最终翻译写入，并覆盖已有翻译。

### 导出运行时文本

用于生成运行时翻译文本文件。

- `OstranautsTranslator.exe runtime -tzh`

支持参数：

- `-t<lang>`

固定导出路径：

- `workspace\exports\runtime\<to>\Text\_AutoGeneratedTranslations.txt`

此命令始终包含草稿翻译。

### 导入运行时漏翻

用于把运行时漏翻报告写回数据库。

- `OstranautsTranslator.exe runtime-miss -tzh`

支持参数：

- `-t<lang>`

默认导入路径顺序：

1. `workspace\imports\runtime-miss\<to>\`
2. 如果该目录不存在，则回退到 `workspace\imports\runtime-miss\`

导入的运行时漏翻始终作为最终翻译保存，并覆盖已有条目。

### 导出原生 Mod

用于把数据库中的翻译导出为游戏 mod。

- `OstranautsTranslator.exe native-mod -tzh`

支持参数：

- `-t<lang>`

`mod_info.json` 会尽可能使用运行时插件记录下来的真实游戏版本。这里的版本就是游戏 UI 中显示的版本，而不是 Unity 引擎版本。

此命令始终包含草稿翻译，并且总会基于最近一次扫描校验源文本哈希。

### 部署当前翻译

用于把数据库中的当前语言翻译直接部署到游戏 mod 目录。

- `OstranautsTranslator.exe deploy`
- `OstranautsTranslator.exe deploy -tzh`

支持参数：

- `-t<lang>`

与无参数自动刷新流程不同，`deploy` 只执行显式部署这一步。

## DeepSeek 批量翻译

### 术语表文件

- 通用术语表：`workspace\reference\glossary.json`
- 目标语言术语表：`workspace\reference\glossary-en-to-<to>.json`

`glossary` 会把通用术语表翻译成目标语言术语表。`translate` 在分批翻译正文时，会优先使用目标语言术语表。

这两个命令现在分别有独立的 system prompt 配置：

- `glossary` 使用 `[TranslateGlossary] SystemPrompt`
- `translate` 使用 `[TranslateLlm] SystemPrompt`

内置默认倾向如下：

- 人名：优先稳定音译
- 其他面向玩家的术语：只要语义可解释，就优先意译
- ID、序列号、型号、热键以及明显的技术标识：保持原样

### 生成通用术语表

`workspace\reference\glossary.json` 不会由 `scan` 自动生成。准备它的最简单方式是：

- `OstranautsTranslator.exe generate`

其内部会调用随包附带的辅助脚本：

- `generate_generic_glossary.py`

解决方案构建会把这个脚本复制到 `OstranautsTranslator.exe` 旁边，因此你可以直接从已部署工具目录运行。脚本会扫描 `Ostranauts_Data\StreamingAssets\data`，从 JSON 和 TSV 文件中提取候选英文专有名词，并写出：

- `workspace\reference\glossary.json`

无参数自动刷新流程也会自动运行这个脚本。

如果你想直接调用脚本，而不是通过 `generate`，那么在已部署工具目录中最简单的用法是：

- `python .\generate_generic_glossary.py`

如果脚本默认的绝对路径不适合你的机器，也可以显式传两个位置参数：游戏数据根目录和输出文件路径。

- `python .\generate_generic_glossary.py "<game root>\Ostranauts_Data\StreamingAssets\data" "<game root>\OstranautsTranslator\workspace\reference\glossary.json"`

输出的 `glossary.json` 是一个按类别分组的 JSON 对象。目前的键包括：

- `people`
- `places`
- `entities`
- `ships`
- `items`

示例：

```json
{
  "people": ["Gideon Pruitt", "Camellia Middlemist"],
  "places": ["K-Leg", "Nnamdi Azikiwe Station"],
  "entities": ["Ayotimiwa", "GalCon"],
  "ships": ["Mimas"],
  "items": ["Black Bull Kape"]
}
```

脚本使用的是启发式提取，因此结果不保证完全准确。生成后请手动检查文件：

- 删除误混进来的普通词
- 补充遗漏的专有名词
- 统一人名、地名、品牌名的拼写

### 仅翻译术语表

- `OstranautsTranslator.exe glossary -tzh`

### 使用 DeepSeek 翻译正文

- `OstranautsTranslator.exe translate -tzh`

### 测试一批正文翻译

- `OstranautsTranslator.exe test -tzh`

`test` 使用与 `translate` 相同的正文翻译设置，但它会在完成一批正文翻译后立即停止，并把这一批结果立刻保存到翻译数据库。这适合在启动长时间完整翻译前，先检查提示词质量和术语表效果。

`translate` 会从 `config.ini` 读取这些值：

- `[LLMTranslate]`：`ApiKey`、`Url`、`Model`、`Temperature`、`MaxTokens`、`BatchSize`
- `[TranslateGlossary]`：`SystemPrompt`、`OverwriteExisting`
- `[TranslateLlm]`：`SystemPrompt`、`TranslationState`、`Translator`、`TranslateGenericGlossaryFirst`、`RefreshGlossary`、`OverwriteExisting`、`IncludeDraft`

当 `translate` 需要先自动生成目标语言术语表时，它会在术语表阶段使用 `[TranslateGlossary] SystemPrompt` 中的提示词，然后再切回 `[TranslateLlm] SystemPrompt` 来处理正文批次。

默认行为：

- 如果 `glossary-en-to-<to>.json` 已存在，则直接用于正文翻译
- 如果目标语言术语表不存在但 `glossary.json` 存在，`translate` 会先生成目标语言术语表，再提交正文批次
- LLM 批量提交进度会显示为进度条
- 每完成一批正文翻译，结果都会立刻写入翻译数据库；因此当 `OverwriteExisting=false` 时，翻译中断后重新运行 `translate` 会从剩余未翻译条目继续
- `test` 使用相同的选择逻辑，但会在第一批正文翻译完成后立刻停止并写库

### 推荐流程

1. 将 `config-example.ini` 复制为 `config.ini`，并设置你自己的 `ApiKey`
2. `msbuild .\OstranautsTranslator.sln /p:Configuration=Release /nologo /verbosity:quiet /clp:Summary`
3. 游戏更新后先启动一次游戏，让插件记录当前 UI 版本
4. 运行 `OstranautsTranslator.exe`

如果你想无视当前版本状态，强制完整重建，请运行：

4. 运行 `OstranautsTranslator.exe rebuild`

如果你不想走自动版本检查，而想手动执行流程，请使用：

1. `OstranautsTranslator.exe scan`
2. `OstranautsTranslator.exe generate`
3. `OstranautsTranslator.exe glossary -tzh`
4. `OstranautsTranslator.exe translate -tzh`
5. `OstranautsTranslator.exe deploy -tzh`
